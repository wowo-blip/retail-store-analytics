# 简历与面试说明

## 可根据自己的理解程度采用的项目描述

**零售门店经营分析与交互式看板｜个人项目**
技术栈：Python、MySQL、Pandas、SQLAlchemy、Plotly、Streamlit

- 基于1000条销售样例记录，搭建 Excel 校验、MySQL 事务导入与 SQL 指标汇总流程，使用来源哈希和金额对账实现重复导入保护。
- 分析3家门店、6类商品的经营表现，将销售额差异拆解为交易笔数项与平均交易金额项，结合品类标准化和大额交易敏感性检查解释差异。
- 使用5000次共同日期簇 Bootstrap 估计门店平均交易金额差异的95%置信区间，并以7日移动块检查时间相关敏感性；开发多条件联动看板与CSV导出。

这里的数字是样本量与实际计算设置，不是业务收益。未做企业部署，不写销售提升、利润增长、客户留存改善或服务真实业务团队等结果。
项目使用开源样例并在AI工具协助下开发；根据自己理解、修改和负责的内容作答，不把别人的数据收集或全部代码都说成独立完成。

## 面试应能解释的六个问题

1. **你解决了什么问题？** 从门店销售额排名进入“交易量与平均交易金额的差异来源”，再说明样本差异的不确定性。
2. **为什么增加数据库？** 练习定义字段、金额精度、主键、事务、可重复导入和统一SQL口径；对于1000行它不是性能必需，不能夸大成大数据系统。
3. **为什么不把所有交易当独立样本？** 同一天的交易可能受共同因素影响，所以共同重抽样日期；日期之间的相关仍是限制，用7日块做敏感性检查。
4. **结果是什么？** Naypyitaw销售额较高但交易数较少，均价项抵消交易量项；三组均值差的95%区间均包含0，不能凭排名认定经营能力优劣。
5. **怎样验证？** 源文件与SQL总数、件数和Decimal金额核对；检查不同维度加总；测试空筛选、参数绑定和异常数据；在浏览器核对筛选和下载交易编号。
6. **有什么限制？** 样本只有89个日历日，采样机制未知；城市和门店一一对应，无法分离城市因素和门店因素；无客户ID和营销数据，不能计算复购、留存或ROI。

## 推荐讲解顺序

先运行看板，展示三家门店的销售额和交易笔数；切换到差异分解；再展示置信区间，说明不确定性；最后打开SQL、质量报告和测试，解释如何保证口径一致。
能亲手修改一次筛选、增加一个SQL指标并验证结果后，再把这些具体能力写入简历。
