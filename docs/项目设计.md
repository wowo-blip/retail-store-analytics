# 项目设计

## 分析目标

围绕三家门店的经营表现，回答销售额差异来自交易笔数还是平均交易金额，以及样本中的均值差异有多大不确定性。通过统一的数据口径连接数据导入、SQL 汇总、统计分析与交互展示。

## 分层结构

| 层次 | 主要文件 | 职责 |
|---|---|---|
| 数据输入 | `data/raw/supermarket_sales.xlsx` | 保留原始样例，记录来源与文件哈希 |
| 校验与导入 | `retail/etl.py`、`sql/schema.sql` | 字段校验、事务写入、金额对账与重复导入保护 |
| 指标查询 | `sql/metrics.sql`、`retail/queries.py` | SQL 聚合、窗口函数和统一筛选条件 |
| 统计分析 | `retail/statistics.py` | 销售额分解、Bootstrap 区间和敏感性检查 |
| 交互展示 | `app.py` | 经营总览、门店差异、统计与数据三个页签 |
| 报告输出 | `retail/report.py` | 从数据库生成 CSV、分析摘要与 Markdown 报告 |

## 数据流程与设计选择

1. 读取 Excel，统一字段名及类型，检查缺失、重复交易编号、数值范围、金额关系和门店映射。校验失败时输出问题记录，不写入业务表。
2. 校验通过后以事务导入 MySQL。金额使用 DECIMAL；以来源哈希标识文件版本，并通过笔数和金额对账防止重复累计。
3. 查询层统一日期、城市、客户类型和品类条件，通过 SQLAlchemy 绑定参数。SQL 负责指标聚合，Pandas 负责绘图整理及重抽样所需的数据处理。
4. 将门店销售额差异分解为交易笔数项与平均交易金额项。结合品类标准化和最高 1% 交易排除检查，观察结论对样本构成的敏感性。
5. 使用 5000 次共同日期簇 Bootstrap 估计均值差区间，以 7 日循环移动块检查时间相关敏感性；固定随机种子并设置样本不足保护。具体公式和假设见 [指标与统计方法](指标与统计方法.md)。
6. 看板与统计分析使用同一筛选范围，支持明细 CSV 和区间结果下载。完整样本报告由单独命令生成。

MySQL 使用项目专用数据目录和端口，导入账户与只读看板账户分离。本地密码由配置脚本随机生成，存放于 Git 忽略的配置文件中。首次配置和启动命令见 [README](../README.md)。

## 验证方式

自动测试覆盖异常数据拒绝、金额精度、SQL 汇总一致性、组合及空筛选、日期边界、参数绑定、只读权限、分解恒等式和 Bootstrap 重现性。

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m retail.report
```

浏览器验收结果保存在 `reports/browser-checks.json`，覆盖页签展示、筛选、空结果、无效日期和 CSV 下载；看板截图与分析报告位于 `reports/`。

## 分析边界

当前输入为 1000 笔样例交易，覆盖三家门店、六个品类和 89 个日历日。没有客户唯一 ID，不能估计复购或留存；门店与城市一一对应，无法区分两者的影响。销售额分解属于描述性分析，Bootstrap 区间不用于认定经营措施的因果效果。
